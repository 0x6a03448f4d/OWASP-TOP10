🔓 M09: Insecure Data Storage - Vulnerable Lab

Learn about mobile data storage vulnerabilities through hands-on examples

⚠️ WARNING: This application demonstrates VULNERABLE code patterns. These examples should NEVER be used in production applications!

Exercise 1: Login & Plain Text Storage

Vulnerability: Plain Text Password Storage

Credentials stored without encryption in database

Try This:

1. Login with credentials: john_doe / Password123!

2. Click "View Database" to see how easily data is accessed

3. Notice passwords, SSNs, and credit cards stored in plain text

Exercise 2: SharedPreferences / UserDefaults Simulation

Vulnerability: Sensitive Data in Plain Text Preferences

Simulates SharedPreferences (Android) or UserDefaults (iOS) storing sensitive data

Try This:

1. Enter sensitive data in the fields

2. Save preferences

3. Click "Extract Preferences" to see how easily it's accessed

Exercise 3: Insecure File Storage

Vulnerability: Plain Text File Storage

Sensitive data written to files without encryption

Real-World Example:

Try storing: password: MySecretPass123

This simulates apps that cache credentials or tokens in files

Exercise 4: Sensitive Data in Logs

Vulnerability: Logging Credentials and PII

Application logs contain sensitive information

What to Look For:

• Passwords in DEBUG logs

• Authentication tokens

• Credit card numbers and CVVs

• API keys

Exercise 5: Insecure Backups

Vulnerability: Sensitive Data in Backups

Backups include all sensitive data without encryption

Real-World Impact:

• Android ADB backup includes app data

• iOS iTunes/iCloud backups sync all data

• Unencrypted backups expose everything

Exercise 6: Base64 is NOT Encryption

Vulnerability: Base64 Encoding Mistaken for Encryption

Many developers think Base64 provides security - it doesn't!

Decode It Yourself:

Copy the encoded string and decode it with:

echo "encodedString" | base64 -d
