What is Insecure Data Storage?

Insecure Data Storage occurs when sensitive information is stored without adequate protection, making it accessible to unauthorized parties. This vulnerability affects applications, databases, file systems, cloud storage, and mobile devices. When data is improperly secured, attackers can:

  • Access plaintext credentials: Retrieve unencrypted passwords, API keys, tokens
  • Steal sensitive data: Extract personal information, financial records, health data
  • Compromise encryption keys: Access poorly protected cryptographic keys
  • Exploit backup files: Find sensitive data in unprotected backups
  • Access cloud storage: Exploit misconfigured cloud buckets and containers
  • Extract cached data: Retrieve sensitive information from temporary storage

Why is it Critical?

Insecure Data Storage is a persistent vulnerability in the OWASP Mobile Top 10 (#2 in 2024) and contributes to various OWASP Web Top 10 categories. It's critical because:

  • Leads to massive data breaches affecting millions of users
  • Results in regulatory fines under GDPR, CCPA, HIPAA [VERIFY SOURCE]
  • Causes identity theft and fraud for affected users
  • Enables lateral movement in compromised systems
  • Found in mobile apps, web applications, and cloud services
  • Often easy to exploit once access is gained

How Insecure Data Storage Works

Common Storage Vulnerabilities

1. Plaintext Password Storage

Storing passwords without hashing or encryption:

# ❌ VULNERABLE: Plaintext storage
def create_user(username, password):
    db.execute("INSERT INTO users (username, password) VALUES (?, ?)", 
               (username, password))  # Password stored as plain text!

# ❌ VULNERABLE: Simple encoding is NOT encryption
import base64
encoded = base64.b64encode(password.encode())  # Easily reversed!

2. Weak Encryption

Using outdated or broken encryption algorithms:

# ❌ VULNERABLE: Using DES (deprecated)
from Crypto.Cipher import DES
cipher = DES.new(key, DES.MODE_ECB)  # ECB mode is insecure!

# ❌ VULNERABLE: Hardcoded encryption key
SECRET_KEY = "my_secret_key_123"  # Key in source code!

3. Insecure Local Storage

Mobile and web applications storing sensitive data insecurely:

Prevention & Mitigation

1. Strong Password Storage (Hashing)

✅ THE PRIMARY DEFENSE FOR PASSWORDS

# ✅ GOOD: Using bcrypt (Python)
import bcrypt

# Hash password
password = "user_password"
salt = bcrypt.gensalt(rounds=12)  # Cost factor
hashed = bcrypt.hashpw(password.encode(), salt)

# Verify password
if bcrypt.checkpw(password.encode(), hashed):
    print("Password correct!")

# ✅ GOOD: Using Argon2 (recommended)
from argon2 import PasswordHasher

ph = PasswordHasher()
hash = ph.hash("user_password")

# Verify
try:
    ph.verify(hash, "user_password")
    print("Password correct!")
except:
    print("Wrong password")

// ✅ GOOD: Using bcrypt (Java)
import org.springframework.security.crypto.bcrypt.BCryptPasswordEncoder;

BCryptPasswordEncoder encoder = new BCryptPasswordEncoder(12);
String hashedPassword = encoder.encode("user_password");

// Verify
boolean matches = encoder.matches("user_password", hashedPassword);

2. Proper Encryption Implementation

✅ Using AES-256 Correctly

# ✅ GOOD: AES-256-GCM with proper key derivation
from cryptography.hazmat.primitives.ciphers import Cipher, algorithms, modes
from cryptography.hazmat.primitives.kdf.pbkdf2 import PBKDF2HMAC
from cryptography.hazmat.primitives import hashes
import os

# Derive key from password
kdf = PBKDF2HMAC(
    algorithm=hashes.SHA256(),
    length=32,
    salt=os.urandom(16),
    iterations=100000,
)
key = kdf.derive(b"user_password")

# Encrypt with AES-GCM (authenticated encryption)
iv = os.urandom(12)
cipher = Cipher(algorithms.AES(key), modes.GCM(iv))
encryptor = cipher.encryptor()
ciphertext = encryptor.update(plaintext) + encryptor.finalize()
tag = encryptor.tag  # Authentication tag

6. Secure Data Deletion

# ✅ GOOD: Secure file deletion
import os

def secure_delete(filepath):
    # Overwrite file multiple times before deletion
    length = os.path.getsize(filepath)
    with open(filepath, 'br+') as f:
        for _ in range(3):
            f.seek(0)
            f.write(os.urandom(length))
    os.remove(filepath)

Real-World Examples

Notable Breaches

1. Adobe (2013) [VERIFY SOURCE]

  • Impact: 153 million user accounts compromised
  • Method: Passwords encrypted with ECB mode (weak), hints stored in plaintext
  • Data: Usernames, encrypted passwords, password hints
  • Lesson: ECB mode reveals patterns; password hints undermined encryption

2. LinkedIn (2012) [VERIFY SOURCE]

  • Impact: 6.5 million password hashes leaked
  • Method: Passwords hashed with unsalted SHA-1 (no salt!)
  • Result: 90% of passwords cracked within days
  • Lesson: Always use salted hashes with proper algorithms (bcrypt, Argon2)

3. Capital One (2019) [VERIFY SOURCE]

  • Impact: 100 million customers affected
  • Method: Misconfigured AWS S3 bucket with firewall vulnerability
  • Data: Social Security numbers, bank account details, credit scores
  • Cost: $80 million fine, $190 million settlement
  • Lesson: Secure cloud storage configuration is critical

4. Uber (2016) [VERIFY SOURCE]

  • Impact: 57 million riders and drivers
  • Method: AWS credentials stored on GitHub, accessed S3 bucket
  • Data: Names, email addresses, phone numbers, driver's license numbers
  • Penalty: $148 million settlement, concealment increased severity
  • Lesson: Never commit credentials to version control

5. Facebook (2019 - Plaintext Passwords) [VERIFY SOURCE]

  • Impact: 600 million passwords stored in plaintext
  • Method: Logging plaintext passwords accessible to 20,000+ employees
  • Duration: Since 2012 (7 years!)
  • Lesson: Never log passwords; hash immediately upon receipt

6. T-Mobile (2021) [VERIFY SOURCE]

  • Impact: 76.6 million customers
  • Method: Unprotected database with customer data
  • Data: SSNs, driver's licenses, names, addresses
  • Lesson: Database-level encryption and access controls essential

Common Vulnerable Scenarios

  • Mobile banking apps: Storing PINs/passwords in plaintext SharedPreferences
  • Healthcare apps: Unencrypted SQLite databases with patient data (HIPAA violations)
  • E-commerce apps: Cached credit card data in local storage
  • Corporate apps: API tokens hardcoded in application code
  • Backup files: Database dumps left in publicly accessible directories
  • Development environments: Production data in development databases
  • Cloud storage: Public S3 buckets containing customer data
  • Log aggregation: Centralized logs containing authentication tokens

Encryption Algorithm Selection

✅ RECOMMENDED

  • Password Hashing: Argon2id, bcrypt (cost ≥ 12), PBKDF2 (≥ 100,000 iterations)
  • Symmetric Encryption: AES-256-GCM, ChaCha20-Poly1305
  • Key Derivation: PBKDF2, Argon2, scrypt
  • Random Generation: os.urandom(), SecureRandom (Java), CryptoKit (iOS)

❌ AVOID / DEPRECATED

  • DO NOT USE: DES, 3DES, RC4, MD5, SHA1 (for passwords)
  • DO NOT USE: ECB mode (reveals patterns)
  • DO NOT USE: Base64 encoding (not encryption!)
  • DO NOT USE: Plaintext, ROT13, simple XOR
