🔐 Cryptographic Failures Lab: Weak Hashing

Understanding Password Hashing Security

⚠️ Educational Purpose Only - This lab demonstrates why certain hashing algorithms are insecure for password storage. Never use MD5 or SHA-256 for passwords in production!

Hash Comparison Tool

Understanding the Differences

❌ MD5 - INSECURE

  • Extremely fast (millions of hashes per second)
  • No built-in salt
  • Vulnerable to rainbow table attacks
  • Can be cracked in seconds

⚠️ SHA-256 - WEAK FOR PASSWORDS

  • Designed for data integrity, not passwords
  • Too fast for password hashing
  • No built-in salt
  • Can be brute-forced with GPUs

✅ bcrypt - SECURE

  • Intentionally slow (adjustable work factor)
  • Built-in salt (unique per password)
  • Resistant to brute force attacks
  • Industry standard for password storage

Key Learning Points

Aspect MD5/SHA-256 bcrypt/Argon2
Speed Very fast (bad for passwords) Intentionally slow (good for passwords)
Salt Not included (must add manually) Built-in automatic salting
Purpose Data integrity, checksums Password storage
Rainbow Tables Vulnerable without salt Resistant (unique salt per password)
Brute Force Resistance Weak (billions/second with GPU) Strong (adjustable work factor)
